# 世界模型（World Model）

一个世界（`worldgen.World`）的**完整逻辑状态**只有三样东西：

```
世界种子（WorldSeed）+ 生成参数（Params，含算法版本）+ 编辑日志（edit log）
```

其它一切——已生成的地形块（chunks）、聚落层（settlements）、道路网（roads）
——都是上述状态的**确定性派生结果**，随时可以丢弃后从零重建，且逐字节一致。

## 1. 坐标系与分块

- 世界是有限的二维方格：`Width × Height` 个单元（cell）。
- 单元是行主序的正方形分块，每块 `ChunkSize × ChunkSize`。
  `Width/Height` 必须能被 `ChunkSize` 整除。
- 块坐标 `ChunkCoord{CX, CY}`，块内用 `(lx, ly)` 索引。
- 世界边界之外是“不可通行的高山”哨兵单元，因此边界处的道路搜索不需要特判。

## 2. 单元（Cell）

每个单元是三个整数定长字段，全部使用整数定点、无浮点超越函数，
保证任意机器、任意 Go 版本下逐位一致：

| 字段 | 类型 | 含义 |
|---|---|---|
| `Height` | `uint16`（0–65535） | 海拔 |
| `Moisture` | `uint16`（0–65535） | 湿度 |
| `Biome` | `uint8` | 由海拔/湿度派生的生态分类 |

生态分类（`classify`）是 `(Height, Moisture, 阈值)` 的纯函数：

| 条件 | 生态 | 道路可通行 |
|---|---|---|
| `Height >= MountainThreshold` | 山地 Mountain | 否 |
| `[0.8·WaterThreshold, WaterThreshold)` | 深水 DeepWater | 否 |
| `< WaterThreshold` | 水域 Water | 否 |
| 低位陆地区间，低湿度 | 荒漠 Desert | 是（代价高） |
| 低位陆地区间 | 草原 Grassland | 是（代价低） |
| 高位陆地，中高湿度 | 森林 Forest | 是（代价中） |

## 3. 地形是纯点函数（无缝的根本原因）

海拔/湿度由版本化的**纯点函数**给出：

```
raw(version, seed, params, x, y) -> (Height, Moisture)
```

某单元的值只依赖 `(x, y)`、种子和参数，**不依赖任何邻居、块坐标、
生成顺序或并发度**。因此：

- 单独生成某块与连同邻块一起生成，得到完全相同的单元；
- 块边界上不可能出现“接缝”：边界两侧只是点函数在相邻整数坐标的取值，
  其连续性与块内部任意相邻单元完全相同；
- 块可以任意并行、任意顺序、任意批次生成。

v1 的点函数由纯整数 value noise + 4 个八度的 FBM 组成（见 `noise.go`），
再经过确定性的“走廊塑形”（`forcePassable`）。

## 4. 结构性可通行走廊（保证任何聚落都可达）

为了让“任何聚落都必须可达”成为**结构性保证**而不是事后补救，v1 的地形
点函数内置了确定性走廊网络（属于地形算法的一部分，因此参与 `TerrainDigest`）：

1. **纵向主干**：每隔 `BackboneSpacing` 列，整列被抬升为干燥陆地，
   形成贯穿全图的脊柱；
2. **聚落安全区**：每个聚落格点（lattice base）周围 5×5 保证为陆地；
3. **横向引道**：从每个聚落基行到最近主干列之间，一条单行陆地引道。

塑形只会把水域/山地“抬升”为干燥陆地，不会制造水域或山地；
它是逐点判定的纯函数，因此跨块同样无缝。这样每个聚落到主干网都存在
一条确定的陆地通路，A* 在无编辑地形上必然能找到路径。

## 5. 聚落层

聚落在一个“带确定性抖动的正方形栅格”上选址：

- 基点点阵：`(ix·S + S/2, iy·S + S/2)`，`S = SettlementSpacing`；
- 抖动：由种子与 `(ix,iy)` 哈希出的确定性偏移，落在
  `[-SettlementJitter, +SettlementJitter]`；
- 间距不变式：`2·Jitter + 2 <= Spacing`，所以不同格点的两个聚落
  中心距离在结构上不可能小于 `Spacing - 2·Jitter`（参数归一化时
  `MinSettlementDist2` 被设为该值的平方）；
- 选址判定只读取候选位置周围固定半径（5×5）的地形：必须全部可通行，
  且平坦度/湿度综合得分 `Suitability >= MinSuitability`。

正因为每个格点的接受决策只依赖其有界邻域内的地形，**一个邻域外的编辑
不可能改变该聚落**，这正是“局部编辑只影响局部”的基础。

- 聚落 `ID = iy·列数 + ix + 1`，只由格点坐标决定，与地形和编辑无关；
- 聚落名由种子与“地形无关参数” `NameSalt` 从格点坐标确定性派生；
- 聚落列表按 ID 升序，是唯一规范顺序。

## 6. 道路层

道路层是在聚落集合上构建的确定性最小生成树（MST）：

1. 先为每个聚落与其栅格近邻（半径 2 格）跑确定性 A*（8 邻接、
   禁止穿墙角 cut-corner）；
2. Kruskal 按 `(cost, A, B)` 全序选边；
3. 若仍有多个连通分量，则在不同分量的聚落对之间补最短跨分量路径
   （无编辑地形下由走廊网络保证存在），重复直到全连通；
4. 边按 `(A,B)` 排序输出，路径统一从小 ID 聚落指向大 ID 聚落。

A* 的开集用 `(f, 单元键)` 全序打破平局，单元键是 `y·Width + x`，
因此搜索路径不依赖 map 遍历顺序或并发。边权由路径经过的地形重新精确
累加（而不是用 A* 内部的 g 值），所以无论从哪个端点搜索，边权一致。

## 7. 编辑层（edit overlay）

编辑是按单元的覆盖层（`editOverlay`），字段级补丁语义：

- `SetHeight`/`SetMoisture` 为 `nil` 表示该字段保持原值；
- 已发布的覆盖层不可变：`apply` 返回一个**新**覆盖层，正在进行的
  生成永远读取稳定快照；
- 同一批次重复提交幂等；不相交单元的批次交换顺序不改变结果；
- 渲染单元时：先算点函数，再叠加覆盖层，最后重新分类生态。

`World.ApplyEdits` 的提交是原子的：先在草稿覆盖层 + 草稿派生层上
验证（含道路全连通检查），通过后才并行重渲染**受影响块**并一次性
交换覆盖层、受影响块与派生层。会导致道路断开的编辑批次被整体拒绝
（返回 `ErrNoRoute`），世界保持原样。

## 8. 并发生成与取消

- `generateChunks` 用有界 worker 信号量并行渲染纯函数块；
- 输出是按坐标键控的值，与 worker 数/调度无关；
- 取消/超时时已完成的块只落在调用方本地切片中并被丢弃，
  不会发布任何半成品（原子提交在 `World` 层完成）；
- 慢块不会阻塞其它块（各自独立竞争 worker 额度），也不会阻塞
  取消的可观察性。
